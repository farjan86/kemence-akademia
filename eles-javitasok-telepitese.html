🔥 Kemence Akadémia — éles telepítés

Két korábban csak a fejlesztői rendszeren tesztelt dolog kivitele az élesre (gtpdqbqxkzodbantdeqk): a heti adatmentés e-mailben, és a 2026-10-22-i penteszt nyomán készült 6 biztonsági javítás. Fentről lefelé haladj.

Készült: 2026-10-26. Mindkét funkció a fejlesztőin már igazoltan, hibátlanul működik — ez csak a kivitel.

⚠️ Titkok: ez a fájl felkerülhet a GitHubra, ezért nem tartalmaz tényleges kulcsokat — csak a lépéseket és <helykitöltőket>. A valódi értékeket (project ref, anon kulcs, az új titkos szavak) csak a Supabase felületére írd be, ide/sehova máshova ne.
Hol találod az éles projekt azonosítóit?
  • PROJECT_REF — a gtpdqbqxkzodbantdeqk (ez az ÉLES projekt; ne a fejlesztőit vagy a demóét használd). Supabase → Project Settings → Data API → „API URL": https://gtpdqbqxkzodbantdeqk.supabase.co.
  • ANON_KEY — Supabase → Project Settings → API Keys → „Legacy anon, service_role API keys" → „anon public" mező. (Publikus, nem titok — ugyanaz, mint a szerveren lévő js/config.js-ben.)
A sorrend logikája (1 perc)

Előbb a heti adatmentést kötjük be — ennek egyik mellékhatása, hogy rögtön az első lépésnél kapsz egy friss, teljes mentést e-mailben, mielőtt a biztonsági javításokhoz hozzáérnénk. Így ha valami a B) részben mégsem úgy menne, mint a fejlesztőin, van nálad egy aznapi, teljes visszaállítási alap. Ezután jön a 6 biztonsági javítás (adatbázis → 2 függvény → a te feltöltésed), a végén egy közös ellenőrző lista mindkettőre.

A. Heti adatmentés e-mailben

Mit kapsz: minden hétfőn (és most, rögtön, egyszer azonnal is) egy levél a csapat-címre, csatolva egy ZIP, benne táblánként egy CSV az adatbázis teljes tartalmával. Részletek: docs/heti-mentes.md.

1
Új titkos szó. Supabase (ÉLES projekt) → Edge Functions → Secrets → Add new → név: BACKUP_SECRET, érték: egy hosszú, véletlen szöveg (32+ karakter).
⚠️ Ne a fejlesztőin használt titkot írd be újra. Generálj egy ÚJAT, kizárólag az élesnek. Írd fel egy jelszókezelőbe — a 3. lépésben kell még egyszer.
2
backup-export függvény telepítése. Edge Functions → Deploy a new function → név pontosan backup-export → a supabase/functions/backup-export/index.ts teljes tartalma → Deploy.
A függvény a send-email-lel közös RESEND_API_KEY / MAIL_FROM titkot használja — ezt nem kell újra beállítani, már megvan.
3
Ütemezés + azonnali teszt-mentés. SQL Editor → a db/05-heti-mentes-cron.sql teljes tartalma, a tetején ezt az öt sort kitöltve: 
project_ref    := 'gtpdqbqxkzodbantdeqk';   -- az ÉLES projekt
anon_key       := '<ANON_KEY>';
backup_secret  := '<az 1. lépésben beállított BACKUP_SECRET>';
utemezes       := '0 4 * * 1';               -- hétfő reggel (6:00 nyári / 5:00 téli idő)
azonnali_teszt := true;                      -- MOST rögtön is küldjön egyet
→ Run. A lefutás végén két NOTICE sort látsz; pár másodperc múlva jön a levél.
4
Ellenőrzés. Nézd meg, hogy megjött-e a levél a csapat-címre (ZIP csatolva, benne ~13 CSV). Ha nem: 
select status_code, content::text from net._http_response order by created desc limit 3;
200 + {"ok":true,…} = minden rendben. 401 = a backup_secret nem egyezik a secrettel. 500 = a backup-export függvény Logs füle mondja meg, miért (tipikusan: a Beállítások fülön nincs kitöltve a csapat e-mail cím).
⚠️ A mentés személyes adatot tartalmaz (vendégek neve, címe, elérhetősége). A fogadó postafiók legyen a cég saját, védett fiókja; a levelet ne továbbítsd tovább.

B. A 6 biztonsági javítás

A 2026-10-22-i penteszt 6 leletét javítja: tárolt XSS az admin foglalás-listájában, rejtett admin-mezők befecskendezése ajánlatkérésbe, nyitott levélküldő mindkét e-mail-függvényben, a csapat e-mail címének nyilvános kiszivárgása, az azonosító-sorszám felülírhatósága, és a feltöltött fájlok szerveroldali méret-/típus-korlátjának hiánya. Mindegyik a fejlesztőin élőben leellenőrizve, regresszió nélkül.

1
4 adatbázis-javítás egy menetben. SQL Editor → a db/j_01-biztonsagi-javitasok.sql teljes tartalma, változtatás nélkül → Run. Egy tranzakció; semmilyen meglévő adatot nem ír felül, nem töröl.
2
send-email frissítése. Edge Functions → send-email → Code → a teljes régi tartalmat töröld, illeszd be a supabase/functions/send-email/index.ts új tartalmát → Deploy.
3
send-ajanlat-email frissítése. Ugyanígy a supabase/functions/send-ajanlat-email/index.ts új tartalmával → Deploy.
Nincs új titok, amit be kell állítani ehhez a két function-höz. Az eddigi „nyers teszt" mód ezután alapból zárva van — csak akkor nyitható meg, ha külön beállítasz egy RAW_TESZT_KULCS secretet is. Élesen ezt NE állítsd be.
4
Frontend csere. Ezt te intézed: futtasd a build.bat-ot → a deploy_web/ mappa tartalmát töltsd fel a Hostinger public_html gyökerébe, a régi fájlokat felülírva (ez hozza a js/config.js-t és a .htaccess-t nem érinti, ahogy eddig sem). Ez a lépés viszi ki a tárolt XSS javítását (admin/js/foglalasok.js).
⚠️ Ürítsd a Hostinger gyorsítótárát feltöltés után (hPanel → Performance/Cache Manager → Purge), különben a régi, javítás előtti foglalasok.js-t kaphatja vissza a böngésző.
