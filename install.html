Utolsó frissítés: 2026-07-30

⚠️ Titkok: ez a fájl felkerül a GitHubra, ezért nem tartalmaz tényleges kulcsokat — csak a lépéseket, a beállítás-neveket és <helykitöltőket>. A valódi értékek (pl. a Resend API-kulcs) a gitignore-olt secrets/titkok.txt-ben vannak.
Hol találod a saját projekted azonosítóit? (Több lépésnél kell — a <PROJECT_REF> / <ANON_KEY> helyére.)
  • PROJECT_REF — a projekt azonosítója. Supabase → Project Settings → API → Project URL: https://<PROJECT_REF>.supabase.co. A web/js/config.js SUPABASE_URL-jében is.
  • ANON_KEY — a publikus „anon" kulcs. Supabase → Project Settings → API → anon / public. Ugyanez a web/js/config.js SUPABASE_ANON_KEY értéke. (Publikus, nem titok.)
Miből áll a rendszer? (1 perc)
  • Frontend (a web/ mappa): a publikus foglaló oldal + az admin felület. Statikus fájlok — élesben a Netlify-on (a kemence-akademia.xyz domainnal).
  • Backend: a Supabase — az adatbázis (foglalások, programok), a belépés (admin) és a levélküldő függvény háza.
  • Levélküldés: a Resend — ez a „posta", ami ténylegesen kiküldi a leveleket.

2. E-mail küldés (Resend)

A leveleket a Resend küldi. Fogalmi magyarázat: docs/email.md. A Resend csak küld, nem fogad — a válaszok a „Csapat e-mail cím"-re (Reply-To) mennek.

2.1 — Resend API-kulcs

  1. resend.com → belépés → API Keys → Create API Key (Sending access elég).
  2. Másold ki a re_… kulcsot (csak egyszer látszik), és tedd a secrets/titkok.txt-be.

2.2 — Domain igazolása (hogy bárkinek mehessen a levél)

  1. Resend → Domains → Add Domain → a küldő domain (élesben a kliens kemence-akademia.xyz-e; dev-ben a saját teszt-domained).
  2. A Resend kiír 3 rekordot (MX + SPF + DKIM, a send. aldomainen). Írd be a domain DNS-ébe (a B) hosting-úton ez a Hostinger DNS Zone Editor), majd Verify.
    Fontos: a rekord oda kell, ahol a domain DNS-ét kezeled — B) esetén Hostinger, A) (Netlify DNS) esetén a Netlify → Domains → DNS. Lásd 4.2.
  3. Részletek + fogalmak (MX/SPF/DKIM): docs/email.md.

3. E-mail automatika (trigger + cron)

Ez NINCS a 01-ben (projekt-specifikus értékek kellenek). Előfeltétel: a 2. szakasz (deploy + secretek) kész.

3.1 — Extensionök bekapcsolása

Supabase → Database → Extensions → keresd és kapcsold BE: pg_net (a trigger + cron http-hívásaihoz) és pg_cron (a napi ütemezéshez).

3.2 — Automatikus visszaigazoló + csapat-értesítő (trigger)

Foglaláskor magától kimegy a visszaigazoló (vendég) + csapat-értesítő (csapat cím). A Database Webhook felület helyett SQL-ből (megbízhatóbb). Az SQL Editorban futtasd le — előbb cseréld ki a két helykitöltőt:

create extension if not exists pg_net;

create or replace function public.trg_uj_foglalas_email()
returns trigger language plpgsql security definer set search_path = public as $$
begin
  if new.statusz = 'jovahagyasra_var' then
    perform net.http_post(
      url     := 'https://<PROJECT_REF>.supabase.co/functions/v1/send-email',
      headers := jsonb_build_object(
                   'Content-Type', 'application/json',
                   'Authorization', 'Bearer <ANON_KEY>'
                 ),
      body    := jsonb_build_object('type', 'INSERT', 'record', to_jsonb(new))
    );
  end if;
  return new;
end; $$;

drop trigger if exists trg_uj_foglalas_email on public.bookings;
create trigger trg_uj_foglalas_email
after insert on public.bookings
for each row execute function public.trg_uj_foglalas_email();

(Ugyanez a fájl: db/15-migracio-auto-visszaigazolo-trigger.sql.) Kikapcsolás: drop trigger trg_uj_foglalas_email on public.bookings;

⚠️ Seed + trigger: ha a demó-seedet (db/04) újrafuttatod aktív triggerrel, minden új foglalás küld egy levelet. Seed előtt kapcsold ki a triggert.

3.3 — Napi emlékeztető (cron)

Mit csinál: minden reggel megnézi, mely program van MÁSNAP, és a jóváhagyott foglalóknak kiküldi az emlékeztetőt.

Előfeltétel: létezzen az „emlékeztető" sablon (a 01-schema-ban benne van; régi DB-nél futtasd a db/13-migracio-emlekezteto-sablon.sql-t), és a pg_cron + pg_net legyen bekapcsolva (3.1).

Beállítás — az SQL Editorban futtasd le (cseréld ki a helykitöltőket):

create extension if not exists pg_cron;
create extension if not exists pg_net;

select cron.schedule('kemence-napi-emlekezteto', '0 8 * * *', $$
  select net.http_post(
    url     := 'https://<PROJECT_REF>.supabase.co/functions/v1/send-email',
    headers := jsonb_build_object('Content-Type','application/json',
                                  'Authorization','Bearer <ANON_KEY>'),
    body    := jsonb_build_object('booking_id', b.id, 'tipus', 'emlekezteto')
  )
  from public.bookings b join public.workshops w on w.id = b.workshop_id
  where b.statusz = 'jovahagyott'
    and (w.idopont at time zone 'Europe/Budapest')::date
        = ((now() at time zone 'Europe/Budapest')::date + 1)
$$);

(Ugyanez a fájl: db/14-migracio-emlekezteto-cron.sql. Napi 8:00 UTC. Ellenőrzés: select jobname, schedule, active from cron.job;)

Azonnali teszt (hogy ne kelljen a napi futásra várni) — pár jóváhagyott foglalónak rögtön küld emlékeztetőt (dátumszűrő nélkül):

select net.http_post(
  url     := 'https://<PROJECT_REF>.supabase.co/functions/v1/send-email',
  headers := jsonb_build_object('Content-Type','application/json',
                                'Authorization','Bearer <ANON_KEY>'),
  body    := jsonb_build_object('booking_id', b.id, 'tipus', 'emlekezteto')
)
from public.bookings b where b.statusz = 'jovahagyott' limit 3;
Fontos a különbség: az ütemezett cron (fent) MÁR tartalmazza a „másnap" dátumszűrőt — magától, naponta fut, és csak a következő napi program jóváhagyott foglalóinak küld. Nincs vele több teendő. Az „azonnali teszt" ezzel szemben egyszeri, dátumszűrő nélküli próba (nem ismétlődik). Ellenőrzés, hogy be van-e ütemezve: select jobname, schedule, active from cron.job;

4. Hosting és élesítés (Netlify)

A frontend statikus (nincs szerveroldali kód), ezért ingyenes statikus hostra való. Éles host: Netlify. A kemence-akademia.xyz dedikált domain (nincs rajta más oldal, sem e-mail), ezért a teljes DNS-t nyugodtan a Netlify-ra bízhatjuk.

4.1 — Frontend fel a Netlify-ra

  1. app.netlify.com → belépés (élesben az ügyfél fiókjában, vagy a fejlesztőében és később átadva).
  2. Add new site → Deploy manually → húzd rá a web/ mappát (drag & drop). VAGY: kösd GitHubhoz és a repo web/-jét add meg publish-könyvtárnak (nincs build parancs).
  3. Kész: kapsz egy <valami>.netlify.app címet. A HTTPS automatikus (Let's Encrypt), külön SSL-vásárlás nincs.
Teszteléshez ennyi elég — a *.netlify.app címen már működik minden. A saját domaint (4.2) csak élesítéskor kell rákötni.

4.2 — Domain rákötése: A-rekord a Netlify-ra (a DNS Hostingeren marad)

Fontos: a DNS/névszerver domainenként külön van — amit itt a kemence-akademia.xyz-vel csinálsz, az a többi domaint (pl. mobilkemence.xyz) nem érinti.

A DNS-kezelést a Hostingeren hagyjuk, és csak ennek az egy domainnek a web-rekordjait irányítjuk a Netlify-ra:

  1. Netlify → a site → Domain management → Add a domain → kemence-akademia.xyz. A varázsló kiírja a pontos értékeket (IP + www cél).
  2. Hostinger → DNS Zone Editor (a kemence-akademia.xyz zónájában):
    • A rekord, név @ → a Netlify által megadott IP (jelenleg 75.2.60.5). A korábbi tárhelyre mutató A-rekordot erre cseréld.
    • CNAME rekord, név www → a <...>.netlify.app cím (vagy amit a varázsló ír).
  3. Terjedés: pár perctől pár óráig. Utána a Netlify automatikusan kiállítja a HTTPS-t (Let's Encrypt) — külön SSL-vásárlás nincs.
Előny: mivel a DNS a Hostingeren marad, a Resend send. rekordjai (2.2) is ott, egy helyen vannak — nem kell két DNS-t kezelni.
Alternatíva (A — Netlify DNS): a fenti helyett a kemence-akademia.xyz teljes DNS-ét is átadhatod a Netlify-nak: a regisztrátornál (Hostinger → Domains → Nameservers) átállítod ennek az egy domainnek a névszerverét a Netlify 4 névszerverére. Ekkor a Netlify kezel mindent (apex + www + HTTPS) magától, de a Resend send. rekordjait onnantól a Netlify DNS-ében kell felvenni. Ez is csak ezt az egy domaint érinti. A B) (fenti) marad az ajánlott, mert a DNS egy helyen marad.

4.3 — Éles ellenőrző lista (EZT NE FELEJTSD!)

  • ⚠️ Töröld a DEV_REDIRECT_TO secretet — különben minden vendég-levél a teszt-címre menne!
  • MAIL_FROM = a kliens igazolt domainje (nem a dev-domain).
  • Admin → Beállítások → Csapat e-mail cím = a valódi csapat-postaláda (pl. akademia@mobilkemence.xyz).
  • A trigger (3.2) és a cron (3.3) a kliens <PROJECT_REF>/<ANON_KEY> értékével fusson.
  • A demó-adat (db/04) NE fusson éles adatbázison.
  • A domain a Netlify-ra mutat (HTTPS zöld), és a www is elérhető.
